# 视频画布适配

## 平台路由与真实能力

用户指定的平台、项目、白板和浏览器优先，不能因为已有神思桥接就把其他平台任务改到神思。先使用可用的官方连接器／API／CLI；没有这些能力时才使用宿主支持的浏览器工具。用户禁止电脑控制时不调用桌面输入工具，右侧网页可通过浏览器工具或已核实的本地接口操作。

网页操作默认使用当前agent宿主的**内置浏览器**。不把Edge／Chrome扩展、扩展文件URL权限或作者机器的浏览器配置作为安装与运行前提；用户明确指定其他浏览器时遵从。内置浏览器的登录态独立，未登录时保留页面并请用户完成登录，不读取或迁移其他浏览器的Cookie、令牌或登录配置。上传使用宿主真实支持的文件选择器接口，先以非敏感合成素材验收；接口不可用时明确阻断，不悄悄切换到扩展。

未指定目标的新画布任务默认**当前可用最新版神思笔记白板**。先按 [shensi-generation.md](shensi-generation.md) 识别协议，不能用旧创作引擎的 `workspaceKind:notebook` 代替新版神思笔记。继续已有任务时遵从绑定中的真实平台、实例与白板，不因默认值更新而迁移、重建或复制运行任务。仅有旧引擎可用时明确说明差异，不冒称已连新版；可继续独立准备素材，再按用户选择或既有绑定接入。用户仅要下载、分析或提示词时不因默认平台而扩展执行阶段。

将四个阶段分开记录：`prepared`（文本与素材齐备）、`bound`（目标原生卡片引用已绑定）、`submitted`（平台已接收真实任务）、`verified`（成片与持久化已检查）。不能用导出成功代替绑定成功，不能用绑定成功代替视频已生成。

连接后读取当前模型的时长、比例、分辨率、图片／音视频上限、音频输入用途、草稿能力和引用格式。平台不支持所需音视频输入时说明缺项，准备兼容方案；不悄悄丢音频、改时长或重配音。参数与引用格式以真实平台为准，不把神思标记当成所有厂商通用协议。

## 原片溯源链（参考视频复刻）

本节连线的用途是**工程路径可视化**：表示截图截取自哪段视频、资产参考了哪张截图、哪段制作采用哪个资产。它不要求执行生成，也不要求使用平台的生成输入端口。来源关系和实际模型参考分别验收；平台某种生成边被拒绝，不等于来源工作流无法展示。

1. 原视频是最高上游的**真实视频媒体节点**：实际导入完整源文件，核对SHA256、时长和可播放状态，保留永久附件路径。分享链接、封面、嵌入网页和文字路径不算原视频已入画布。相同源片在同一画布按SHA256复用一个节点，不为每段再上传整片；不同来源／不同剪辑版本分开登记。
2. 对每张原片截图／抽帧记录源视频ID、实际解码PTS（秒）和所覆盖的原片区间；请求seek时间不能冒充实际PTS。拼接联系表须记录每格来源，来自多个视频时标明全部真实来源。建立 **原视频 → 对应源帧** 的可视化来源关系，每张帧都能反查原片。补看、新提取的帧也要补齐这一步。
3. 源帧继续连接实际由它指导的资产图／分段说明卡；资产图标明采用它的生成卡。将全片流程由左到右排成 **原视频 → 源帧 → 生成资产 → 分段生成卡**；没有新生成资产的段落仍保留源帧到对应段落的分析来源关系。多段在最右侧纵向依次排列，共享节点一图多连，不重复上传同一参考。优先使用能随节点保存的原生独立关系线或画布箭头，上游右侧指向下游左侧，不接卡片顶端。箭头两端必须对应具体对象，不用无归属的装饰线冒充关系。
4. **来源关系与模型引用是两套映射。** 原片截图／抽帧只用于分析或资产图生成，不直接作为视频生成参考；视频卡片实际绑定验收后的资产图及本段需要的音视频。原视频作为溯源根节点，不自动进入所有卡片的 `references`、引用编号或提交内容。平台将所有入边自动当模型参考时，优先使用其独立关系线或明确的引用白名单；没有独立线时用来源说明节点／关联展示节点承载同一条可视化路径，注明对应真实媒体node ID、名称与帧PTS，分段说明映射到真实生成卡。说明链不连接实际生成卡的输入口，不复制完整生成提示词、不伪称AI生成或执行过生成。不能为了画完整链将原帧误送生成模型。
5. 回读核验原视频文件身份、可播放性、每帧时间与归属、可视关系的两端／说明映射、段落映射；再打开生成栏检查模型参考没有混入溯源帧。刷新后复查节点、附件与关系仍存在。只上传素材而未表达来源，或只写了JSON未在画布展示，不能称来源工作流完成。独立关系线与说明节点方案均可满足来源可视化；分别记录所用方式，不将间接说明链声称为直接媒体边，也不将来源可视化完成混称为模型引用绑定完成。

原视频大于平台导入上限时，先核实其真实大文件导入方式；没有支持时保留完整本地原片与溯源计划，明确原片节点／边尚未绑定。不要静默替换为封面、低清代理或截短片；用户同意使用代理时另记其SHA与完整原片对应关系。网页画布也遵循此来源链，实际不支持视频节点、连线或播放时逐项说明限制并交付可迁移包，不伪造已支持。

## 所有平台共用的不变量

- 一段对应一个原生生成卡片。完整提示词在该卡片操作栏中，保留所有五项格式、质感、光照及实际台词／歌词，不写“同上”。
- **初始站位／初始空间关系中提及的人物、场景和道具，必须将对应的已有参考全部插入对应描述，并真实绑定到本段卡片，不得遗漏。** 先从该段正文逐项列出对象，展开「四位导师」「三徒」等合称，再核对项目当前确认的资产映射；不能因近景、远景、背影、背景人物或暂未直接出镜而省略已提及对象。相同对象在该段初始站位中再次出现时，仍在对应位置插入其引用，使用同一真实资产，重复引用不重复上传。
- 逐卡核验「全部提及对象 → 对应已有资产 → 文内引用位置 → 实际参考与连线 → 回读编号」闭合；只列名称／路径、只放上游素材或只插一次总清单均不算补齐。没有对应资产时列明缺项，按既有缺失资产规则处理，不虚构引用；平台引用上限容纳不下时说明具体冲突并给出兼容方案，不静默删参考或删对象以通过检查。
- 上游共享素材复用；按当前平台实际引用数组与编号规则建立每次引用序列。编号可能按媒体类别独立，也可能按混合数组全局编号，不能统一假设。上传异步完成可能重排素材，最后按回读顺序重编引用；溯源关系不占用生成参考编号。
- 真正上传文件并核对目标卡片里的就绪状态、时长与文件身份；路径字符串、外部缩略图或上游节点可预览不能证明下游引用已经可用。
- 原片／演唱音频按该段裁切，记录原曲区间、局部起点、采样率、时长与SHA256。不靠文字保证口型，不改变速度、音高或音轨顺序。
- 要求新版本时保留原版，新卡片位于原版右侧并沿用同一段纵坐标；多段按行对齐版本列。生成结果、运行任务和用户的其他内容保留。
- 创建草稿与消耗积分的提交分离。已有授权只覆盖明确范围；提交未知时按真实任务ID找回，不换ID盲目重提。
- 完成后回读正文、参数、引用、位置与版本关系；能刷新时再检查持久化。没有连接能力就交付素材包并说明未迁入。

## 神思

读取 [shensi-generation.md](shensi-generation.md)，先用随包 `scripts/shensi_canvas_probe.py` 只读识别新版神思笔记或旧创作引擎，再进入对应协议文档。`scripts/shensi_bridge.py` 仅用于旧引擎；新版不得调用旧 `/api/workspace/*` 或旧草稿接口。端口、真实配置及目标ID动态读取，不固定作者电脑路径。已有笔记／工作区只做最小增量修改，保留 `expectedStateStamp` 冲突检查。原片溯源节点与真实视频生成参考分别管理。

## 即梦画布

执行前读取 [jimeng-canvas.md](jimeng-canvas.md)，默认在内置浏览器按真实页面完成能力预检。以下步骤是操作要求，不是已经通过的兼容性证明。

1. 读取用户已打开的官方画布，确认当前模型和参考模式；不另开陌生站点代替，不推测私有API。
2. 在目标位置新建视频卡片，填写完整提示词和真实可选参数。上传本段所需图片、对应裁切音频；从画布引用时核对上游文件的真实身份。
3. 等待该卡片所有素材上传完成，查看失败标记；仅恢复失败引用，不删除源素材或旧版卡片。以最终素材顺序建立引用映射。
4. 使用页面真实提供的 `@` 引用选择器插入素材。预览中的 `@图片1`／`@音频1` 只是语义标签，必须经目标控件绑定后才算完成；不声称纯文本已变为原生引用。
5. 对每张卡片回读正文、时长、音频长度和素材状态。遇系统文件框受限时优先使用浏览器支持的文件上传接口；不要不断重开无法操作的弹窗。

## LibTV

读取 [libtv-canvas.md](libtv-canvas.md)，使用官方 `libtv` CLI。若宿主已经安装 `libtv-cli` Skill，读取其对应命令文档；否则先读取 `libtv --help` 和目标子命令帮助，以当前版本为准。不要拼私有HTTP请求绕过CLI。已实测CLI 1.1.3／1.2.0拒绝原视频资源节点直接连接图片资源节点；该生成工作流边的限制不阻断采用来源说明节点完成可视化。按专项文档验证说明路径及模型引用隔离，准确报告采用的是间接说明链，不声称直接媒体边已支持。

常见已知操作形态（运行前核实当前帮助）：

```text
libtv node list -p <实际画布UUID>
libtv model search --type video
libtv model "实际模型展示名"
libtv upload "本段音频" -p <实际画布UUID> -t audio -f <实际音频文件>
libtv node --x <旧卡右侧X> --y <旧卡Y> create "段落-v2" -p <实际画布UUID> -t video
libtv node "段落-v2" -p <实际画布UUID> --left <真实上游nodeKey> --prompt <完整提示词>
```

模型参数使用实时 schema 的字段及枚举。`--prompt` 中的真实引用为 `{{Node <nodeKey>}}`，节点必须存在并已连到目标入边；同名节点使用 `nodeKey` 消歧。`-s model=...` 使用CLI要求的实际模型名字，不把其他平台模型ID照搬。

准备草稿时不加 `--run`。明确核对并获准提交时才按CLI运行；`--run` 等待本次任务终态，不再套另一套重复提交／轮询逻辑。参数通过进程参数数组或平台支持的结构化输入传递，不把用户提示词拼成 shell 命令。

## 其他画布

沿用上述同一素材与溯源计划，读取实际官方能力后映射 `create_node`、`upload_asset`、`connect_provenance`、`bind_reference`、`set_draft`、`readback`。这几个词是操作契约，不是已经存在的厂商 API。兼容网页画布时分别检查视频附件、来源连线、生成引用、位置与草稿保存能力，不把模型引用连线和分析来源线混用。缺少位置控制时说明布局限制；缺少音频驱动时交付音频与口型修正方案；缺少接口时导出素材包，不伪造可导入格式。

## 离线素材包格式

准备标准JSON，路径相对于计划文件；`{{asset:ID}}` 只属于触手的离线中间格式：

```json
{
  "schema": 1,
  "assets": [
    {"id": "hero", "kind": "image", "path": "refs/hero.png"},
    {"id": "voice", "kind": "audio", "path": "refs/line.wav", "duration_seconds": 8}
  ],
  "segments": [
    {
      "id": "S01", "title": "演唱", "duration_seconds": 8,
      "aspect_ratio": "16:9", "resolution": "720p",
      "refs": ["hero", "voice"],
      "prompt": "[主要事件]：{{asset:hero}}按{{asset:voice}}的原声演唱。其余五项内容按本段补全。"
    }
  ]
}
```

```text
python scripts/canvas_bundle.py --plan plan.json --out-dir exports --platform generic
python scripts/canvas_bundle.py --plan plan.json --out-dir exports --platform shensi
python scripts/canvas_bundle.py --plan plan.json --out-dir exports --platform jimeng
python scripts/canvas_bundle.py --plan plan.json --out-dir exports --platform libtv --bindings bindings.json
```

每次产生独立子目录，不覆盖旧版本。实际所需素材统一复制到全局 `_media`，按SHA256去重，并在 `manifest.assets` 登记；各段读取 `references.file`，不假定存在独立的 `segment/media` 目录。适配器按全局SHA在目标画布复用同一真实媒体节点，再建立各段引用，不按分段重复上传。逐卡仍记录类别、编号和每次引用顺序。WAV时长会从文件头核验；压缩音视频应先用媒体工具测出时长填入计划，打包器不伪称已解码测量。

复刻计划另加以下 `provenance`，并将原视频、源帧和实际资产都登记在 `assets` 中；它与 `segments[].refs` 独立，不能为了打包原片而把它加入生成参考：

```json
{
  "provenance": {
    "source_videos": ["original"],
    "frames": [
      {"asset_id":"frame01","source_video_id":"original","timestamp_seconds":0.04}
    ],
    "edges": [
      {"from":"asset:original","to":"asset:frame01"},
      {"from":"asset:frame01","to":"asset:hero"},
      {"from":"asset:hero","to":"segment:S01"}
    ]
  }
}
```

这是合并到上方计划的片段，不是独立完整计划。`original` 必须是有真实文件与实测 `duration_seconds` 的video资产；`frame01` 是image资产，时间为该源视频的实际PTS秒数，范围为 `[0, duration_seconds)`。每张源帧必须有来自其原视频的显式边；每段都要经源帧回溯到原片。使用 `asset:ID` 与 `segment:ID` 指定边，不允许循环、未知ID或把分段作为上游。多源帧、联系表等复杂来源另保留逐格时间映射，不将不支持的多源关系强塞进单帧字段。

导出器将来源图写入 `provenance/graph.json`，图中包含SHA256、相对媒体路径、帧时间和右口→左口的连线计划。原片和源帧即使不在生成引用中也会复制到共享媒体目录；按SHA复用文件，不为每段复制整片。相同源帧内容换资产ID也不能绕过不得直接作为视频生成参考的约定。图标记 `analysis_only:true`、`prepared` 和原生绑定未验收；适配器据实际平台导入后才记录真实节点、边和回读状态。旧的无溯源图原创计划仍可使用；参考视频复刻不能因字段可选而省略来源图。

`--platform shensi` 只生成既有神思语义标记预览，不识别实际实例，也不是新版神思笔记导入器；新版可先用 `generic` 包，按真实 `references` 数组和原生别名规则重编引用。不能把导出文本标记当作已绑定引用。

LibTV绑定文件形如 `{"hero":"实际nodeKey","voice":"实际nodeKey"}`。这些值必须来自CLI读取结果，脚本只做格式编译，不证明节点存在或已连边；输出依旧标记为 `prepared`，绑定和生成状态由平台回读后记录。即梦输出保留语义标签，等待页面原生引用控件绑定。此包不自动提交任何生成。
