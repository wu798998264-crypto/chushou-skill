# 触手的短视频与漫剧生产线

按用户本次目标选择生产线，保留当前阶段与已确认版本。仅下载、仅转写、仅提示词、仅更新Skill时，停在要求的范围，不自动推进整条生产线。以下为执行工作流，不代表宿主已经具备所有工具；神思内优先使用当前白板提供的真实工具，工具缺失须说明。

## 一、短视频线

1. **素材入口**：本地视频直接读取；视频链接按下载规则解析和校验；也可直接提供原创脚本、人物参考或歌曲。已有文件和资产优先复用。
2. **观察／梳理**：参考视频核对时长、音轨、台词、实际解码PTS、切点、动态、运镜和关键道具，快动作加密复核；原创按用户脚本和必要拍摄设计建立事件记录，不伪造原片证据。
3. **脚本与提示词**：保留完整台词和动作因果；通过AI导演（二）将内容编为五项结构，单条最长30秒且服从平台上限，一时间范围一种景别和一种运镜，保证自然语速。按 [ai-video-director-2.md](ai-video-director-2.md) 处理导演规则与触手既有约定的衔接。
4. **资产**：盘点人物、生物、场景及必要道具；已有资产复用，缺失人物／场景按本次授权生成，道具仍先核对。3D与真人按各自规范，用户要求先看样图时先样图后批量。漫剧的三类样图确认不自动扩大为每个短视频的强制节点。
5. **画布准备**：参考复刻展示原视频→真实源帧→资产→分段的来源路径；原创使用脚本／已确认设计来源。分段卡片右侧纵排，共享参考左侧复用；完整提示词只写入生成栏，插入真实参考，核对时长、16:9默认比例及平台能力。
6. **核对与生成**：默认交付可编辑、可替换参考的待生成卡片。用户核对并点击生成；用户另有明确代提交授权时按其具体范围执行。收起操作栏，保留用户主动关闭行为；结果持久化回读和成片核验分别记录，不承诺逐帧零差异。

## 二、漫剧线

### A. 原剧素材与校订文稿

按 [drama-transcription.md](drama-transcription.md) 核对剧名和目录，下载本次授权的全集／选集，逐集转写并保存原始稿。结合原音和可见字幕校正错别字、专名和说话人，再完成标点与排版。原始稿、校订稿、依据、待核项分别保存；按真实整数集号汇总，缺集或未校对不能声称全集完成。单独文稿任务在这里结束。

### B. 原剧全集大纲

进入改编生产线后，基于**全部已校订集次**整理原剧全集大纲：主线、人物关系、每集事件与因果、人物状态、伏笔及回收、关键转折、阶段高潮和最终结局。每项能回溯到真实集号；区分原剧事实、机制分析和待核推断。对理解剧情必需但台词未说明的视觉事件，补查对应视频，不能只读台词猜剧情。材料不全只能交阶段大纲并列缺集，不命名为已完成全集。

同时使用 [漫剧剧本Skill](manju-script.md) 提炼叙事、情绪和追看机制；没有可靠传播数据就不宣称已证明爆款成因。

### C. 人工参与改编全集大纲（必须等待）

把原剧全集大纲及有依据的机制分析交给用户。用户参与决定新剧人物、关系、核心冲突、事件链、反转、结局、集数与单集时长；可按用户要求共同讨论和修改，但Agent给出的建议稿不能自动当成用户已批准的新大纲。

**只有用户明确确认某个版本的原创全集大纲，才进入逐集剧本。** 等待期间可以整理已有证据、资产候选及一致性记录，不能自行编完新大纲后越过确认。新的原创故事应有独立人物、具体事件和表达，不只改姓名复用原剧桥段与对白。若用户直接提供且明确确认现成原创全集大纲，可从此处接续，不重复下载、转写或要求提供样本。

### D. 漫剧剧本Skill逐集写作

以已确认的新大纲为唯一剧情基线，按 [manju-script.md](manju-script.md) 顺序撰写本次要求的逐集剧本；记录大纲版本和集号。每集包含承接状态、本集目标、完整场次、人物动作与回应、台词、局势变化、兑现／悬念及下集衔接。保持角色知道的信息、道具去向、伤势和时间地点连续，最终集收束核心冲突。

执行新剧单次发言不超过40字、不能靠换行或无效动作拆句规避的规则；该规则**不用于删改原剧转写或用户已确认的原文**。当前剧本若与确认大纲实质冲突，标明具体影响并由用户确定大纲修改，不能擅自重写整剧。

### E. AI导演（二）逐集转换

本次剧本写作范围完成并自检后，读取AI导演（二）规则，将每集分别转换为可执行视频提示词。每集按自然叙事边界拆生成段，记录集号、段号和预计时长，保留全部剧情、台词和表演，不将40字上限当成一镜必须讲完的时长标准。每段完整展开共同质感、光照和参考用途。

遵从 [ai-video-director-2.md](ai-video-director-2.md)：全程不出现字幕、无BGM的既有默认不变；3D漫剧不能被旧导演模板强制转成真人，每条30秒是上限而非强行填满。用户明确只要剧本时不开始转换。

### F. 三类资产样图与风格确认（必须等待）

1. 按全集／本次已写完剧本范围建立资产总表，复用已有合格资产，列出待新增与特殊状态版本。3D人物按灰底四栏规范，真人按原白底三栏；生物、道具、场景各用自己的规范。
2. 从真实剧本中选择**人物、道具、场景各一项，每类先出一张样图**，同时交付实际提示词与上游参考。若已有图可作为该类风格样图，先复用供确认，不为新流程重做；若剧本无该类资产，说明不适用，请用户确认省略，不凭空造道具凑三类。
3. 先列具体样图对象、提示词和本次生成配置。用户明确要求本流程的三类样图时，该范围包含一张道具样图；此前已确认对象不重复询问。其余道具和批量清单仍须核对，付费配置与用量遵从当前宿主已有授权。仅说“完善流程”不授权生成任何样图。
4. **等待用户对三类样图和统一风格明确确认后，才批量生成剩余资产。** 部分类型未确认时，只修改对应样图，不擅自全量启动。风格、模型或关键设计变更后重新确认受影响样图；同一已确认风格不逐集重复询问。
5. 用户对样图、风格及批量资产范围确认后，执行缺失资产批量生成，完成身份、结构、版式与文件完整性检查；待核和失败项明示，不按计划数量宣称全齐。全部完成后供用户核对，用户确认资产无误才正式插入分段生成卡。

### G. 画布绑定与最终手动生成

按用户指定的平台／既有绑定接入；未指定时默认最新版神思笔记。按集组织白板／分区，按段纵排真实生成卡；将当前完整提示词写入生成操作栏，逐项插入对应人物、道具、场景及其他必需参考。共享资产不重传。原剧来源链作为分析依据保留，不把原剧帧误接成原创新剧的视频输入。

回读提示词、引用身份和顺序、比例、实际可用时长、版本与保存状态。**默认停在待用户核对、待用户点击生成按钮的状态**，不因写完剧本、确认样图、批量图片完成或插入画布就自动提交视频。

用户可直接在原生操作栏改提示词、替换参考，或以保留的图片生成提示词与上游参考重新生成资产。保留旧资产／草稿／结果版本；新图验收后更新对应引用与提示词标记，再回读，不覆盖无关卡片或进行中的任务。用户确认最终提示词与参考后自行点击生成；另有明确代提交指令时再按该指令执行。

## 三、版本、状态与交付

用项目内的生产记录保存两条线及当前阶段，可采用 `production-state.json`：`line`、`stage`、`sourceCoverage`、`sourceOutlineVersion`、`approvedOriginalOutlineVersion`、逐集脚本／提示词版本、三类样图ID／SHA及确认记录、批量清单、资产验收、画布绑定与 `videoSubmission`。确认记录须对应真实用户回复及具体版本，不能伪造或把超时当同意。

剧情、大纲或风格变化时只使受影响下游项失效，保留旧版本与历史确认依据；重新计算依赖并标记待更新，不能用旧确认批准新版本。图片清单保留 `generation_prompt`、`reference_paths/reference_node_ids`、生成通道／配置、版本、SHA及状态；生成提示词和参考不只留在临时聊天里。

流程阶段与画布 `prepared → bound → submitted → verified` 分别记录；样图确认不等于批量完成，画布绑定不等于视频已生成。确认等待由用户要求触发，精确说明当前交付版本与下一步，不把整个任务笼统标成失败。
